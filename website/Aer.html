Indoor Air Quality Monitoring System V1

   This project is the largest and most comprehensive I have worked on, serving as my Bachelor's thesis. It required me to integrate all my existing hardware knowledge and even learn new programming languages. The project started from a personal desire to monitor indoor air quality, allowing me to know precisely when and how much to ventilate my room for a constant supply of fresh air. I started researching this subject, and then I mapped out the architecture, concluding that the most critical parameters to track were temperature, humidity, dust density and CO2 levels.

   I found a sensor to measure humidity and temperature, the HTU21D, which offers high precision and a wide operating range. For dust detection, I used the GP2Y1010, an optical sensor that detects indoor dust density. It utilizes an infrared LED and a photodiode positioned diagonally; when dust particles pass through the intersection of the light path, the IR light reflects/refracts, triggering a proportional voltage response on the photodiode. For airborne gas detection, I used two sensors with distinct sensitivities to different types of gases: the MQ-135 and the MQ-2.

   My initial idea was to utilize a Raspberry Pi 4 as a server to access all the data from my phone. However, the problem was that most of the sensors were analog, and I needed an analog-to-digital converter (ADC). Due to cost and time constraints, I used an Arduino Uno instead. I programmed the Arduino to collect all the data from the sensors and send it through USB to the Raspberry Pi. For the Raspberry Pi, I wrote a script to open serial communication to receive the data and append a timestamp upon arrival. Once the data was received and classified, it was sent to the Firebase database.

   To ensure seamless data access, I developed a native Android application in Android Studio using Java. The main dashboard displays the most recent sensor readings and the current air quality status. For historical analysis, I created dedicated screens with dynamic charts that plot each environmental parameter over a rolling three-day window.

   This project was highly challenging at times because I encountered numerous obstacles. When I tried to implement the charting screens, the date and time were not displaying correctly. While debugging the code, I noticed a function that seemed to alter the timestamp values unpredictably. After some online research, I discovered that the charting library required the date and time to be formatted in milliseconds (Unix timestamps), whereas my initial code sent them in a standard text format. After finalizing the application, another issue came up the data points on the charts became too dense and unreadable after a few days. To fix this, I created a cleanup function that automatically deletes database records older than three days.
