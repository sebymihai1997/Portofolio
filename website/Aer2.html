Indoor Air Quality Monitoring System V2

   This is the second version of my indoor air quality project. I kept the same goal as before: monitor the air in a room and know when it needs fresh air.

   In the first version I had too many cables and the system only worked while connected to a laptop. With V2 I wanted a cleaner setup that could run by itself and send updates without extra hardware attached.

   I kept the same sensor types: temperature and humidity, dust density, and gas level. The ESP32 collects the readings, smooths out noise, and sends the values over WiFi to a dashboard that can be viewed remotely.

   The goal was to make the system useful every day, not just a prototype. Now it can measure air quality continuously, store readings when the network is down, and update the dashboard as soon as the connection returns.

ESP32 Firmware Raspberry Pi Server

The Motivation Behind the Project

   According to reports from the U.S. Environmental Protection Agency (EPA), the indoor environment can be two to five times more polluted than outdoor air. Given that our modern, energy-efficient buildings are often hermetically sealed, pollutants can accumulate dangerously over time.

   Gases like Carbon Dioxide (CO2) and Volatile Organic Compounds (VOCs) are mostly odorless and colorless. Long-term exposure to these poor air quality indicators can reduce cognitive function, trigger allergies, and cause severe respiratory issues. This system was built to provide an affordable, portable, and continuous monitoring solution to bring awareness and mental peace to our daily enclosed environments.

System Architecture

   The sensor node is powered from a small battery pack. Two 18650 Li-ion cells are charged through a TP4056 module, and a MT3608 boost converter raises the voltage to 5V for the sensor electronics.

   The main controller is an ESP32 board. It reads the IAQ and gas sensors over I2C, while the dust sensor uses an analog input. A small 16x02 LCD shows the current values directly on the unit.

   The sensors used in this version are:

     BME680 for indoor air quality and environmental data

     SGP30 for TVOC and equivalent CO2 measurements

     HTU21D for temperature and humidity

     GP2Y210 for dust density

   All readings are sent by WiFi to a Raspberry Pi server node. The Pi runs a web server, receives the incoming data, and stores it in a database so the dashboard can show the latest values and history.

   I also built a simple MQTT backend so the ESP32 can send data live to a dashboard. The device keeps working even if WiFi drops by saving measurements locally and sending them later.

   The schematic shows how all the sensors are wired to the ESP32 microcontroller. Each sensor has its own power regulation and connection path.

   The PCB layout brings everything together on a compact board. All the components are arranged for easy assembly and good signal integrity.

Software & Network Communication

   The software architecture is modular and designed for resilience. The ESP32 node is programmed in C++ and handles data acquisition, utilizing the Bosch BSEC library to fuse raw sensor data into an accurate Index of Air Quality (IAQ).

   For communication, the system uses the lightweight MQTT protocol. The ESP32 acts as an MQTT publisher, sending telemetry data to a local Raspberry Pi 4 acting as the broker. To prevent data loss during network instability, the ESP32 is equipped with connection retry logic and fallback display functions.

   The backend runs on Python, employing multithreading to manage the MQTT ingestion while simultaneously serving a web interface. The data is parsed, timestamps are standardized to UTC, and everything is safely logged into an SQLite database via SQLAlchemy.

Real-World Testing: 24-Hour Case Study

   To validate the system, I conducted a 24-hour continuous test in a 12 square-meter room. The scenario mimicked typical winter conditions: windows and doors mostly closed with no mechanical ventilation. The subject performed daily activities such as sleeping, studying, and reading.

   Key Findings:

  • CO2 Accumulation: With windows closed, eCO2 levels steadily rose to average around 680 ppm, leading to reported losses in concentration and mild headaches. Upon opening the window, levels rapidly dropped to baseline.
  • VOC Spikes: Volatile Organic Compounds hovered around 800 ppb with windows closed, occasionally spiking over 1400 ppb during specific activities. Ventilation immediately cleared the accumulated pollutants.
  • IAQ Index: The overall air quality degraded significantly within just an hour of closing the window, proving that simply "airing out" a room once a day is insufficient for maintaining a healthy environment.

   After the first version, I focused on making the readings easier to trust. I added calibration for the sensors and filtered the data so sudden spikes are less distracting. The result is a system that feels more stable.

   This version improves reliability by adding network buffering, automatic sensor calibration, and a more modular software architecture. The firmware is simpler, the data is cleaner, and the whole setup looks more finished.
